# 2.5 小时冲刺 · 收敛总方案

> 产品 Agent · 2026-10-11 · 决策终稿（非研发执行稿，研发见 `app/spec/v2-implementation-spec.md`）
> 约束：距企业演示录制不足 2.5 小时；演示形式 = 成片 + 功能讲解混剪（容错高，可预选素材）

---

## 0. 三秒结论

1. **开源项目：全部"为我所用"，但不是"集成代码"**。Video2X 走外部 CLI 调用（规避 AGPL 传染），MoneyPrinterTurbo / NarratoAI 只搬架构思路，SkyReels-V2 记入技术雷达不动。详见《产品决策：开源集成可行性分析》。
2. **五项需求里只有 2 项能在 2.5 小时内真正落地**（多提示词批量输入、Kling 适配器修正），其余（配乐、提示词真分镜、视觉质检）演示靠"预置素材 + Mock 流程"补位，代码留到赛后迭代。
3. **一个必须先纠正的事实**：你给**阿里云充的 18 元用不了 Kling**——可灵是快手平台，需在可灵开放平台单独充值；且 18 元连 1 段 4K 都不够（Kling 3.0 4K = ¥45/15s，1080p = ¥18/15s）。见 §4 风险与提醒。

## 1. 开源项目最终用法（回答你的原问题）

| 项目 | 能否"全部加进项目" | 实际用法 | 依据 |
|------|------------------|---------|------|
| MoneyPrinterTurbo | ❌ 不能代码级 | ✅ 搬架构思路：LLM 服务层独立（LiteLLM 式统一接口）、服务边界拆分 | MIT，Python 栈 ≠ Node.js |
| NarratoAI | ❌ 不能代码级 | ✅ 搬质检思路：多模态 LLM 抽帧判断"画面是否符合提示词" | MIT，思路可 Node 重写 |
| Video2X | ❌ 不能代码级（AGPL-3.0 传染） | ✅ **外部进程调用**：`upscaler.js` 只做 spawn + 参数 + 结果，不复制/链接其源码 | AGPL 仅约束衍生作品，CLI 调用安全 |
| SkyReels-V2 | ⚠️ 现在不用 | 记入技术雷达：本地无限长视频，需 GPU + 通读 Skywork 自定义协议 | 量产阶段再评估 |

**结论**：你的产品拿它们的**能力**，不拿它们的**代码**。演示时可讲解"超分复用 Video2X 引擎、质检复用多模态 LLM 思路"，这是加分项不是负担。

## 4. 风险与提醒（必须正视）

### 4.1 ⚠️ 阿里云 18 元 ≠ Kling（事实错误，先纠正）
- Kling 是快手平台，充值入口是**可灵开放平台**（klingai.com），与阿里云账户完全无关。
- 18 元预算严重不足：Kling 3.0 **1080p = ¥1.2/s**（15s = ¥18/段），**4K = ¥3/s**（15s = ¥45/段）。演示要 5 段 1080p 需要 ≈ ¥90。
- 如果这笔钱想用上：只有转**阿里云百炼通义万相（Wan）视频模型**（DashScope API）才有意义——那是另一套模型/接口，且需另开百炼服务。**二选一，别两头空**。

### 4.2 时间风险：Kling 官方 API 开通流程
- 可灵开放平台 API 需实名 + 可能审核，**2.5 小时窗口内未必完成**。这是本项目最大的时间风险。
- 兜底方案（三层，按序降级）：
  1. 官方 API 可用 → 真实联调（最优）
  2. 网页端（app.klingai.com）免费额度人工生成 → 下载片段喂流水线（演示"半自动"，讲解时说明 API 接口已就绪）
  3. Mock 模式跑完整流程（稳定，但画面是演示色测试片，仅展示流程不展示画质）

### 4.3 演示内容策略（成片+讲解混剪，容错已较高）
- **成片展示段**：用真实 Kling 片段（预生成，宁缺毋滥，3-5 段即可），不现场等生成。
- **功能讲解段**：录屏展示多行提示词输入 → 成本预估弹窗 → 实时进度/质检 → 产物目录，这部分用 Mock 跑也成立（流程真实性 > 画面真实性）。
- **关键话术**：把"超分 = Video2X 引擎调用"、"质检 = 多模态 LLM 内容理解"作为工程亮点讲，这是开源借鉴的加分面。

### 4.4 勿在 2.5h 内触碰的部分（明确不做）
- ❌ 配乐模块、HDR、超分代码（演示阶段用剪辑软件补音轨/预置 4K 素材即可）
- ❌ 技术栈迁移 Python（1-1.5 周，赛后决策）
- ❌ 模式化流水线重构（2-3 天，赛后）
