## 0. 产品一句话定位

**输入一个风光主题（如"冰岛""星空"），自动产出 30-60 分钟 4K 风光长视频，可选配乐 / HDR / 8K，用于电视屏保与展厅大屏循环播放。**

参考风格锚点（B 站样片）：
- 样片 1：《世界最震撼的美景 4K HDR 杜比》—— 1 小时国家/地区主题风光片、治愈系、轻音乐（53 万播放）
- 样片 2：《8K 星空风光延时摄影》—— 延时摄影感、星空/银河/极光、氛围乐（172 万播放，全站排行最高 26）

风格关键词：纯风景无人、多场景切换（每镜头 5-15 秒）、缓慢运镜、金色/蓝调时刻光影、治愈或震撼氛围。

## 1. 验收框架（企业考察五维）

| 维度 | 考察点 | 本项目对应物 |
|------|--------|-------------|
| 成片品质 | 4K 画质、风格贴合样片、无瑕疵片段 | Kling 3.0 原生 4K + 片段级质检 |
| 成本 | token/API 费用透明可控 | 成本预估弹窗 + report.json 实测成本记录 |
| 效率 | 生成时长、自动化程度 | 并发生成 + 模式化流水线（draft 快速验证） |
| 工程可复用 | 参数复用、一键复跑 | run.config.json 全参数快照 + replay |
| 协作交付 | 文档、产物归档、可交接 | 本 spec 目录 + 标准化产物目录 |

硬性指标：端到端成功率 ≥ 90%；一次质检通过率 ≥ 85%。

## 2. 现状盘点（截至 2026-10-10）

### 已完成（约 70%）

```
后端（Node.js）
├── 7 步线性流水线        src/pipeline.js     提示词优化→分镜→批量生成→拼接→无缝循环→转码→终检
├── 适配器架构 5 家       src/generators/     mock / seedance / kling / agnes / siliconflow
├── 两层任务状态机        src/taskManager.js  task + clips，JSON 持久化，支持断点续跑
├── 质检模块              src/qualityChecker.js 黑帧/模糊/重复/时长/拼接/循环/转码
└── FFmpeg 封装           src/videoProcessor.js 拼接/无缝循环/转码（路径已配置）

前端（单文件 public/index.html）
├── 任务创建 / 实时监控（WebSocket）
├── 失败分析（错误分类 + 修复建议 + 片段级明细）
├── 成本预估弹窗（非 Mock 模型生成前确认）
└── API Key 管理（localStorage + 测试连接按钮）
```

### 缺口清单

| 缺口 | 影响 | 状态 |
|------|------|------|
| Kling 适配器是占位实现 | 端点/鉴权未按官方文档验证，真实联调未做 | **迭代 2 修正** |
| 超分 / HDR / 配乐模块全缺 | 无法交付 4K+、HDR、带音轨成片 | 迭代 3 新建（超分走 Video2X 薄封装，D11） |
| 提示词未对齐样片风格 | 出片风格不受控 | 迭代 2 LLM 真分镜 + 模板库 |
| 分镜是模拟实现 | pipeline.js 第 2 步 sleep 800ms，非真分镜 | 迭代 2 接入 llmService |
| 不支持多提示词批量输入 | 需求要求一次输入 5/10/120 个不同场景，当前只能单提示词复制 N 份 | **迭代 2 P0**（含行级【主题】标签，P1） |
| 质检只有技术指标 | 拦不住"内容跑偏"（要雪山给沙漠） | 迭代 2 视觉内容质检（多模态 LLM） |
| 无 run.config.json | 无法一键复跑，工程可复用考察失分 | 迭代 3 |
| 流水线线性全量执行 | 无法 draft 快速验证，浪费生成费 | **迭代 2 模式化改造** |
| S3 上传未做 | 交付归档不完整 | 迭代 4（可选） |

## 3. 关键决策记录（为什么这么走）

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| D1 | 架构 | Node.js 后端，不做纯浏览器方案 | API Key 安全 + CORS |
| D2 | 段时长 | **15 秒**（放弃 30s 单段） | 样片镜头语言本就是 5-15s 多场景切换；展厅观众预期场景切换，拼接痕迹不构成问题；30s 原生仅 Seedance 2.5 且无 4K |
| D3 | 主力模型 | **Kling 3.0 原生 4K（¥3/s）—— 推荐，待盲测确认** | 国内可直接调用的最便宜原生 4K；备选 Seedance 2.5 1080p+超分（¥3.74/s） |
| D4 | 分辨率基线 | 1080p 起步，**否定 720p** | 720p→4K 是 3x 放大，细节糊化软化 |
| D5 | 后处理 | 超分/HDR/配乐/转码全部**可选化**（模式化流水线） | draft 模式零后处理成本快速验证；满意后补跑增强，生成费零重复 |
| D6 | 8K 路径 | 4K 母版 → Real-ESRGAN 2x 超分 | 无模型直出 8K；4K 起步的 2x 远好于 1080p 起步的 4x |
| D7 | HDR | FFmpeg zscale+PQ 打样，展厅链路确认后升级 Topaz | 先零成本验证；诚实定位为"HDR 容器输出"非真 HDR |
| D8 | 配乐 | 仅 CC0 / 免署名音源（Pixabay Music、Freesound CC0） | **禁用 MusicGen**（CC BY-NC 协议禁商用）；量产授权安全 |
| D9 | 价格基准 | 以官方 API 定价为准，不用第三方中转价估算 | 曾误用 ¥0.06/段中转价导致成本低估 10 倍，已修正 |
| D10 | 海外模型 | Veo 3.1 / Runway / Luma / Pika 全部排除 | 中国大陆无法直接调用 API（网络+支付+地区限制） |
| D11 | 超分实现 | **Video2X 外部 CLI 薄封装**（0.5 天），不自研 Real-ESRGAN 封装（1-2 天） | 成熟稳定；AGPL-3.0 以独立进程调用不传染 |
| D12 | 2.5h 冲刺范围 | 只做 P0 两项：多提示词批量输入、Kling 适配器修正；其余演示补位 + 赛后迭代 | 时间窗口不允许 1-2 天架构改动 |

**成本参考（30 分钟成片，Kling 3.0 4K 15s×120 段）**：生成 ≈ ¥5,400；超分/HDR/配乐为本地算力，边际成本 ≈ 0。draft 模式（1080p）验证一轮 ≈ ¥2,160。

## 4. 目标架构：核心链 + 可选增强层

```
【核心链 · 必选】                    【增强层 · 可选，依赖顺序固定】
提示词优化 → 分镜 → 批量生成  →  拼接 → 无缝循环 → 超分 → HDR → 配乐 → 转码 → 终检
   (片段质检/重试/并发)          默认开  默认开   默认关 默认关 默认关 默认开
```

五档执行模式（预设写死在 config.js `PIPELINE_MODES`）：

| 模式 | 用途 | 包含步骤 |
|------|------|---------|
| `draft` | 快速验证内容风格 | 核心链 + 拼接 |
| `standard` | 日常交付 | + 超分 4K + 配乐 |
| `delivery` | 最终成片全量 | + 超分 + HDR + 配乐 + 转码 |
| `segments` | 输出片段包供人工精剪 | 仅核心链 |
| `custom` | 前端勾选任意组合 | 依赖校验后执行 |

**补跑能力**：任务落盘每步独立状态，支持 `--only upscale,audio_mix` 从母版补跑增强步骤，不重复生成。

## 6. 风险登记册

| 风险 | 等级 | 缓解 |
|------|------|------|
| Kling 4K 风景画质不如预期 | 高 | 迭代 0 盲测决策门；备选 Seedance 2.5+超分 |
| 4K 单段 ¥45，失败重试成本高 | 中 | 适配器实现"失败降档 1080p 重试"；maxRetries=1 |
| 无 GPU 机器无法本地超分 | 中 | 环境检测 + 明确报错；云端超分 API 作备选 |
| HDR 为合成输出非真 HDR | 低 | 交付文档如实标注；展厅链路先验证 |
| 120 段拼接的整体成功率 | 中 | 单段成功率 95% 时整体仅 0.2% 全成功——靠"部分失败跳过 + 补跑"机制兜底，不求单轮 100% |
| CC0 曲目量有限 | 低 | manifest 情绪标签化管理，首批 ≥20 轨 |
| Video2X AGPL-3.0 协议 | 中 | 仅外部进程（CLI/Docker）调用，不复制/链接其源码；交付文档注明"独立进程调用，非衍生作品" |
| Kling 开放平台 API 开通/审核时间 | 高 | 2.5h 窗口内若未开通：降级为网页端免费生成人工喂入；再降级 Mock 演示流程 |
