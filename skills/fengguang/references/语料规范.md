# 语料：把已核验画面拆成提示词要素

> 适用：手上一批实拍片段，要变成「字段 → 提示词」的训练 / 评测对。
> 与 `片源筛选.md` 的分工：那边判「能不能挂上电视」，这边判「能不能拆成字段」。
> 依据：2026-10-27 产出的 **37 行 base + 102 条单维度变体 / 21 支源片**
> （`prompt-corpus-20261027/corpus.jsonl`、`variants.jsonl`），以及一轮抽查与差分复核（§4、§7）。
> **行数按 jsonl 实测**，不按口述。

---

## 0. 换标准：可拆性四问

屏保判「放不放得住」，语料判「**拆不拆得开**」。四问全过才入语料：

1. **地貌能命名吗？** 能写成"风蚀垄脊 / 丹霞赤壁 / 冰碛垄"而不是"一片山"。
2. **光能指方位吗？** 能说出时刻 + 从哪来 + 冷暖，而不是"光线很美"。
3. **机位与运动说得清吗？** 高度（航拍 / 地面 / 贴地）+ 一条运动主轴；两条主轴就拆不干净。
4. **画面有字吗？** 有字**不等于不能用**，但必须标 `overlay`——否则训练集会把字学成画面元素。

缺一条：降级为负样本，或换片段。**不要用"同题材推断"补缺**，那是在教模型编。

## 1. 字段（v0.2）

### 必填（17）

| 字段 | 取值 | 谁能定 |
|---|---|---|
| `id` | `dx-01` 这类短 id，全表唯一 | 人 |
| `src` | B 站 BV 号 | 人 |
| `t` | `mm:ss`，分钟可超过 60（长片用） | **必须对得上 sprite 的 index** |
| `place` | 国家/省 · 具体机位 | 标题/简介 + 画面 |
| `theme` | 九主题之一 | 人 |
| `landform` | 地貌专名，逗号分隔 2–4 个 | 画面 |
| `light` | 时刻 + 方位 + 冷暖，一句 | 画面 |
| `camera` | 机位高度 + 焦段 + 运镜 | 画面（焦段见 §2） |
| `motion` | 画面里在动的东西，一个主轴 | 画面 |
| `atmosphere` | 空气感/能见度 | 画面 |
| `lock` | 结尾锁在哪 | 人（写提示词时定） |
| `palette` | `极冷极淡` / `暖浓` / `暗底暖星云` | 画面 |
| `grade` | `dramatic` / `cinematic-calm` | 人（按用途） |
| `overlay` | `true` / `false` | 画面 |
| `overlay_note` | overlay=true 时写清楚"标了什么、在哪" | 画面 |
| `frame_source` | `videoshot` / `videoshot(aid)` / `manual` / `inferred` | 人 |
| `prompt` | 七段全量中文提示词；**不写分辨率、不写声音/配乐/音效** | 人 |

### 选填（v0.2 新增，用来堵窟窿）

| 字段 | 作用 |
|---|---|
| `verified` | **看过帧**才允许 `true`。缺这个字段 = 旧语料，按未核验处理 |
| `inferred` | 推断字段名数组，如 `["camera.focal_mm","light.time"]` |
| `negative` | 负样本（水印/字卡/片尾），不用于生成 |
| `aurora_type` | `弧` / `帘幕` / `贴地辉光` / `冠冕`（见 SKILL.md §十一） |
| `foreground` | 极光前景：雪林 / 湖面 / 海岸线 + 小镇灯火 |
| `note` | 负样本用途、来源提示（如"油管超分"）、反例说明 |

### 扩写集（`variants.jsonl`）额外字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `variant_of` | base 的 `id` | 同组；切 train/eval 时不许拆开 |
| `changed` | `camera-move` / `light-azimuth` / `lens` | 只许改一个维度 |

变体可**继承** base 的 `overlay_note` / `frame_source` / `verified`，不必逐条重抄；
但 `overlay` 必须与 base 一致（变体不能凭空多出水印）。

**两条硬规矩：**

- `frame_source` 有值 **≠** `verified=true`。取到图不等于看过图。
- `verified=true` 的行，`inferred` 必须为空；反之亦然。二者同时存在 = 自相矛盾。

## 2. 480×270 能判什么、不能判什么

这是平台逐帧缩略图（sprite 单格）的分辨率，也是这批语料的证据上限。

| 能判 | 判不了（只能推断） |
|---|---|
| 地貌类型、层理/节理、有没有雪/苔藓 | **焦段**（24 vs 35 vs 50） |
| 光从哪来、明暗方向、冷暖、有无硬影 | 快门/曝光/光圈、是否长曝 |
| 机位高度（航拍高位/中位/贴地/地面） | 真实画质、码率、压缩程度 |
| 单主轴运动（云/水/光斑/帘幕） | 细微质感（颗粒、锐度、色深） |
| 色板冷暖倾向、饱和度大致档 | 精确亮度/饱和数值（要用 `analyze_frames.py`） |
| 有没有字、字大概在哪 | 字幕轨（烧录 vs 软字幕） |

**结论**：`camera` 里的 `24mm / 35mm / 50mm` 是**同题材推断值**，写的时候必须承认——
要么进 `inferred`，要么在 `camera` 里写"约"。拿它当测量数据会污染训练。

## 3. 反拆六步（顺序不能反）

1. **取 sprite**：`node tools/bilibili_sprite.js <BV> --out ./_sprites`
2. **定 t**：sprite 的 `index[]` 数组给每格的秒数（**不是等间隔**，且首格常重复）。
   先看 `index`，再定 `t`；反过来"先写 t 再找画面"必错。
3. **命名地貌**：查 `references/词库.md` §1，拒绝"山/水/风景"。
4. **读光**：时刻（日出前/侧逆/阴天散射…）+ 方位 + 冷暖，一句写完。
5. **定机位与运动**：只留一条主轴；两条就换片段。
6. **定色板与档位 → 写七段 prompt**：主体句 / 运动 / 运镜 / 光线 / 氛围 / 质感 / 结尾留白。

每步都有"判不了"的出口：写 `inferred`，不要硬编。

## 4. 抽查：怎么抽查，以及我踩过的坑

**正确动作**：sprite 是 10×10 联络表（整图 4800×2700），**单格只有 480×270**。
把整图缩到屏幕上看，单格里的背景会糊成一片——必须把目标格**裁出来、放大 3 倍**再看。

**踩坑记录（2026-10-27）**：抽查 `mt-01`（希夏邦马，`t=00:00`）时，我先看整张联络表，
第 0 格像"黑底大字标题卡"，于是判"时间戳与内容不符"。把第 0 格裁出来放大后：
**背景就是日照金山**（峰顶金黄、云海冷蓝），标题只是压在下三分之一。结论反转——
这一行是对的，只是带 `overlay`。

**三条教训**：

1. **看整表会误判**；裁单格 + 放大再下结论。480×270 的缩略图在联络表里只剩约 270×150。
2. **标题卡与好画面可以共存**：`overlay=true` 不等于内容不能用，它只说明"要标/要裁"。
3. **"未核验"不等于"是编的"**。拿不准就标未核验，但不要把对的判成错的——
   这次差点把一条正确的日照金山行删掉。

**抽查清单**（每批抽 3–5 条）：第 0 格、`t` 对应格、随机中段格；
看三件事——地貌能不能命名、光从哪来、有没有字。

## 5. 污染与负样本

| 污染源 | 例子 | 处理 |
|---|---|---|
| 台标 + 地名 | 中国国家地理《丹霞》每段 | `overlay=true` + note；可裁则裁 |
| 设备水印 | 罗弗敦 8KRAW / DJI Inspire 3 | `overlay=true`；同素材优先换无水印版 |
| 章节标题卡 | CC-Chen 两小时电影每章开头 | `negative=true`，prompt 写"（负样本，不生成画面）" |
| 片尾署名 | 格拉丹东黑底手写体 | `negative=true` |
| 烧录字幕 | 星空延时片 | `overlay=true`；软字幕轨另记 |

**训练纪律**：`overlay=true` 的行只能当负样本或先裁切，**不能当"干净参考"**。
否则模型会学到"画面右上角应该有个标"。

## 6. 入库门槛（三态）

| 状态 | 条件 | 能进哪 |
|---|---|---|
| **可用** | `verified=true`，无 overlay（或已裁） | SFT / 评测 |
| **待核验** | `verified=false` 或字段在 `inferred` 里 | 只进待核验池，**不进训练** |
| **负样本** | `negative=true` | 单独一类，训练"识别并剔除" |

体检命令（零依赖，退出码 0 = 无结构错误）：

```bash
node tools/check_corpus.js <corpus.jsonl>                        # 只查 base
node tools/check_corpus.js <corpus.jsonl> --variants <v.jsonl>   # 连扩写集一起查
node tools/check_corpus.js <corpus.jsonl> --json                 # 机器可读
node tools/check_corpus.js <corpus.jsonl> --strict               # warning 也算失败
```

它查：必填字段、枚举、id/prompt 重复、`t` 格式、overlay 无 note、缺 `verified`、
负样本标记、aurora 字段、禁用词（含**分辨率 / 配乐 / 音效**）、高光控制、结尾锁死；
带 `--variants` 时再查：`variant_of` 是否存在、`changed` 是否合法、**除声明维度外逐字节一致**、
`camera` 内部的「焦段 / 运镜」有没有越界、变体 id 是否 `<base>-vN`、每条 base 是否 3 条。

**2026-10-27 基线**：
- base 单独查：37 行 / 21 源片 / **error 0** / warning 38（37 条缺 `verified` + 1 条缺高光控制）
- 带 102 条变体：合计 139 行 / **error 0** / warning 38
  （37 条 INFERRED + sp-04 UNVERIFIED；v3 曾有 21 条 error，v4 修复；dx-03 缺高光已在 v4.1 补齐）

## 7. 扩写：1 条 → 4 条（v0.2 实际做法）

每条 base 扩 3 条，加 `variant_of` + `changed`，**只改一个维度**：

| 变体 | 改什么 | 约束 |
|---|---|---|
| `camera-move` | `camera` 的运镜部分（焦段不许动） | 按机位族分池；FPV 只配「沿崖横切/爬升」，不许配「缓推」 |
| `light-azimuth` | `light`（+ 必要的 `atmosphere` 修补） | 按题材分池；极光/星空不许换正午；主体句有"月光"的不许换"无月夜" |
| `lens` | `camera` 的 mm（机位与运镜不许动） | 航拍 24/28/35，地面 16–50，FPV 16/18/20 |

**三条必须程序验证的事**（v3 实测 102 条里 **21 条不合格**；v4 修复后 error 0）：

1. **单维度差分**：除 `changed` 声明的字段外，其余与 base **逐字节相等**；
   `camera` 还要拆成「焦段」与「机位+运镜」两半再比一次。
2. **一条运动主轴**：`静机位` 不许配 `缓推/横移/滑行/环绕`；`缓推` 不许配 `滑行/环绕/俯冲`。
3. **跨句一致性**：换光后「月光/月面」要跟着改成「星光/星点」，否则出现"无月夜 + 月光"。

**光依赖 → N/A**：base 的 `motion` / 主体句若含只属于原光位的现象（光斑、光柱、云隙、
日照金山、月光/月影、长影），这一组的 `light-azimuth` 变体**不生成**（标 N/A），
而不是联动改 motion——联动就破坏单维度。实测反例：`dx-02`「光斑沿岩壁缓慢移动」换成侧逆光后不成立。

**v3 实测反例**（`expand.mjs` 的 camera 归一化 bug，**v4 已修**）：

- 17 条 `light-azimuth` 变体连 `camera` 一起改了——换光时顺手把机位句重排了；
- 4 条 `lens` 变体把「缓推」塞进原本只有「贴壁滑行」的镜头；
- 结果：`dx-02-v2` = "贴壁滑行 超广角，16mm，缓推"（滑行 × 推镜，双主轴），
  `ds-02-v2` = "静机位微移 … 缓推"（静止 × 推镜，自相矛盾）。

**所以"只改一个维度"不能靠代码自觉**，必须跑差分校验：

```bash
node tools/check_corpus.js corpus.jsonl --variants variants.jsonl
```

它会报 `MULTI_DIM`（改了声明外字段）、`LENS_CHANGED_MORE`（换焦段顺手改运镜）、
`MOVE_CHANGED_MM`（换运镜顺手改焦段）、`AXIS_CONFLICT`（双主轴）。

**去重**：两条 prompt 前 30 字一样 = 改得不够；`DUP_PROMPT` 会抓到完全相同的。

**token 必须整词**：`平行脊线横移` 若词表里只有 `横移`，替换会留下「平行脊线缓推」
（跟踪 × 推镜）。扩写词表要按**最长匹配**排，并给每条 base 打印"识别到的 move"，识别不到就别硬替换。

## 11. 要公开发布时（比自用多五条）

自己训练只要"心里有数"，公开发布要能**逐行裁决**：

1. **`rights` + `author` 必填**。缺一个就不进发布版。`author` 至少到频道名 + 来源链接。
2. **未知即排除**：`unknown` 与 `aggregator-unknown` 同等处理，不做"默认保留"。
3. **不发画面**：sprite 截图、联络表、原片都不进发布包；只发"要素 + 自写提示词 + 来源链接"。
4. **发布版单独构建**：`corpus.publish.jsonl` / `variants.publish.jsonl` / `sft-*-publish.jsonl`，
   原文件保留全量，别在原文件上删行。
5. **附 NOTICE**：写明"描述为人工撰写、画面版权归各摄影师/机构、本包不含画面"。

| rights | 能进发布版？ | 条件 |
|---|---|---|
| `original-branded` | ✅ | 署名 + 不带水印画面 |
| `originator-branded` | ✅ | 署名机构，条件同上 |
| `aggregator-unknown` | ❌ | 搬运号来源不明，风险不可控 |
| `unknown` | ❌ | 没查清就是不能发 |

**别把"描述"当"画面"**：提示词是人工写的描述性文本，和画面版权是两件事；
但"照着别人的片子写"仍有署名义务，且搬运号本身的风险不会因为你只写文字而消失。

**先分清发布的是什么**：

- 只发**成片**（纯 AI 生成、语料内部用）→ 不需要发布版、不必删 aggregator 行；
  红线只有一条：**成片里不许混入任何源片画面**（哪怕 1 秒空镜）。
- 发**语料/模型** → 按本节五条走，未知即排除。

## 12. 多批次合并（A/B/C → 单一语料）

分批补素材时，每批一个 `batch-*.jsonl` 很方便，但训练前必须合成一份，且规则要固定：

1. **id 全局唯一**：负样本统一 `neg-` 前缀，保留 `source_id` 回溯。
2. **评测组冻结**：老语料抽出的 8 个评测组保持不变；**新增组一律进训练集**。
   每次补数据都重抽评测组，历史指标就不可比了。
3. **隔离行不进组**：`verified=false` 的行（如 sp-04）不参与扩写与切分，它的变体要删掉。
4. **顺序固定**：merge → `expand.mjs` → `make-split.mjs` → `check_corpus.js --variants`。
5. **四数对账**：base 行数、组数、SFT train/eval、三元组 train/eval，四个数字写进 `split.json`。

合并后**实测**（2026-10-27 三批）：base 50（37+13，含 6 条负样本）、可用组 43、
变体 129、SFT 140/32、三元组 105/24、负样本 20。

## 10. 切训练 / 评测：按组，不按行

102 条变体**不是** 102 个独立样本——同一 `variant_of` 共享主体句、结尾锁句与大半字段。

- 以 `variant_of` 为组做 GroupShuffleSplit：**base 与它的 3 条变体同进同出**。
- 同一 `src` 有多段时再往上按 `src` 分层（一条片子只出现在一侧）。
- 留出评测集要**整组留**；数量按组算，不按行算。
- 差分任务的三元组 `(base_prompt, variant_prompt, changed)` 也不许跨集。

**实测事故**：三元组文件曾把 8 个评测组的 24 条也写进去（102 条全量），
一旦拿它训差分，评测集就等于开卷。正确做法是切成 `triples`（训练组 75 条）
与 `triples-eval`（评测组 24 条）两个文件，并跑一次组归属校验。

按行随机切 = 把同一素材的答案抄进评测集，指标会假高 10–20 个点。
