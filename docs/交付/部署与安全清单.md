# 部署与安全清单（交付方必读）

> 生成：2026-11-12。适用版本：本仓库当前 `main`。
> 凡标「实测」的都给出了可复述命令；标「未验证」的表示本机无法验证（例如没有 HTTPS 证书、没有真实公网环境）。

---

## 一、部署前必须做的 9 件事

| # | 事项 | 为什么 | 怎么做 |
|---|---|---|---|
| 1 | **换掉管理员密码** | `.env.example` 默认 `AUTH_USER=admin`，初始密码可能被沿用 | 首次登录后在 `/members.html` 改；或先在库里建新账号再停用 `admin` |
| 2 | **改 `AUTH_PASSWORD` 为空并重建账号库** | 账号一旦建好，`.env` 里这两行就**不再生效**，容易误以为改了就生效 | 确认首次启动时终端打印的初始密码，登录后立刻改 |
| 3 | **确认 `AUTH_ENABLED=true`** | 设成 `false` 会**完全关闭登录墙**（页面、API、媒体全部裸奔） | `GET /api/status` 无需登录能通 + 页面能直接进 = 被关了 |
| 4 | **对外只暴露 HTTPS** | 会话 cookie 在明文 HTTP 下可被同链路嗅探；本项目的 cookie 是 `HttpOnly` 但不含 `Secure` | 前面挂 nginx/Caddy 终止 TLS，`proxy_pass http://127.0.0.1:3001` |
| 5 | **反代后置时设 `TRUST_PROXY=true`** | 否则服务看到的客户端 IP 恒为 `127.0.0.1`：登录失败锁定会变成「锁所有人」，日志也失去意义 | `.env` 里 `TRUST_PROXY=true` 并重启；**直连公网时保持 false** |
| 6 | **HTTPS 部署时设 `COOKIE_SECURE=true`**（或不设，靠反代透传 `X-Forwarded-Proto`） | 让会话 cookie 只走加密链路 | 同上；⚠ 本机 `http://localhost` 不要开，否则登录不了的 |
| 7 | **改掉 `.env` 里所有第三方 Key** | 交接包里的 Key 属于交付方，交出去就等于给了别人计费能力 | 逐个换成接收方自己的 Key；旧 Key 在厂商后台吊销 |
| 8 | **改掉数据库密码并轮换** | 仓库里没有 Key（见下表「已核查」），但 `.env` 在交付方磁盘上是明文 | 先在 Supabase 改密码，再更新 `.env` 的 `DATABASE_URL`，重启验证 |
| 9 | **确认 `data/` 不对外** | `data/` 下有任务 JSON、日志、用户表（JSON 模式）、波形缓存 | 只通过 3001 访问，不要把 `app/data` 挂成静态目录 |

> 探活用 `GET /healthz`（新增，只回 `{"ok":true}`），不要用 `/api/status`（它含 pid、启动时间、模型名）。

## 二、本次加固改了什么（2026-11-12）

| 问题 | 严重度 | 改动 | 位置 |
|---|---|---|---|
| `/output`、`/clips`、`/bgm` 三个媒体目录**不跟随登录墙**：知道 URL 就能下载成片 | **高**（公网部署=成片泄露） | 新增媒体鉴权中间件：`AUTH_ENABLED=true` 时三个前缀都要求有效会话；`false` 时放行（验收脚本依赖） | `server.js` 媒体目录段之前 |
| `/api/bgm/mix` 用 `startsWith('output')` 防穿越，`output/../../server.js` 可绕过 | **高**（任意文件读 + 拼进 ffmpeg 命令行） | 改为「解析后必须仍在 `output/` 内」，并拒绝含 `" % & \| < > ^` 与控制字符的路径 | `server.js` `/api/bgm/mix`；`src/utils/security.js` |
| 渲染 ffmpeg 命令用 `\"` 转义引号 —— **Windows cmd.exe 不认这种转义**，`%VAR%` 还会在引号内展开 | **高**（命令注入面） | `q()` 改为**拒绝**危险字符而不是尝试转义；三处调用点统一 | `src/processors/audioMixer.js`（3 处） |
| 无任何安全响应头 | 中 | 加 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`（刻意不加 CSP：会打坏现有页面） | `server.js` 顶部 |
| 反代后 `X-Forwarded-For` 被完全忽略 | 中（登录锁定误伤） | 新增 `TRUST_PROXY` 开关，默认仍不信任（防伪造） | `src/auth.js` `getClientIp()` |
| 会话 cookie 无 `Secure` | 中 | 新增 `COOKIE_SECURE` / 反代 `X-Forwarded-Proto` 自动判断 | `src/auth.js` |
| 公开的 `/api/status` 含 pid/启动时间/模型名 | 低 | 保留（前端用它检测前后端版本错位），另加最小 `/healthz` 给反代探活 | `server.js` |

## 三、已核查、确认不是问题的地方

- **真实密钥没有进过 git**：`.env` 从未被跟踪；带密码的数据库 URL（`用户名:密码@`）在提交历史里 0 命中（`git grep -l "…:" HEAD`）。
- **配乐上传**（`POST /api/bgm`）已做得比较严：后缀白名单、文件头嗅探（RIFF/ID3/ftyp/OggS）、20MB 上限、服务端生成文件名（用户不控制落盘路径）。
- **登录墙本身**：`HttpOnly + SameSite=Lax`、常量时间密码比较、失败 5 次锁 5 分钟、认证存储不可用时返回 503 而不是放行（fail-closed）。

## 四、仍然存在的风险（如实告知，未修）

1. **没有 CSP**：页面能被注入脚本时没有第二道防线。加 CSP 需要先梳理 `web/` 的内联样式与 UMD vendor，属于独立任务。
2. **配乐上传是 64MB base64 JSON**：一个已登录用户可以一次性占用较多内存。内网/小团队可接受；公网建议在反代上限制请求体。
3. **没有 HTTPS 终止能力**：本项目只提供 HTTP，TLS 必须由反代承担。
4. **无漏洞扫描/依赖审计**：本机没有 npm，`npm audit` 无法运行；依赖版本只能按 lockfile 固定。
5. **未验证**：真实公网环境下的上述加固（本机只能验证逻辑与接线，无法验证反代真实透传行为）。
