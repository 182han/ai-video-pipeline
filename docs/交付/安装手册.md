# 安装手册（从零到跑通）

> 面向：接收方部署工程师。目标：拿到仓库后，在**一台干净机器**上跑起来并自检通过。
> 本手册所有命令都实测过（Windows + Node 24），Linux/容器差异在每节末尾单独标注。
> 配套自检脚本：`node scripts/doctor.js`（缺什么会直接告诉你）。

---

## 0. 先看这张表：你需要准备什么

| 依赖 | 版本要求 | 是否必需 | 说明 |
|---|---|---|---|
| Node.js | **20 或以上** | 必需 | 仓库 Dockerfile 用 `node:20-slim`；开发机实测 Node 24 |
| 包管理器 | pnpm（推荐）或 npm | 必需 | `pnpm-lock.yaml` 完整；`package-lock.json` 已过期（见 §2） |
| ffmpeg / ffprobe | 5.x 以上（实测 8.1） | 必需 | 拼接/转码/质检/抽帧全靠它 |
| 磁盘 | ≥ 20 GB 空闲 | 必需 | 成片与片段很占空间 |
| 数据库 | 无 / PostgreSQL | 可选 | 不配就是本地 JSON 模式，零依赖 |

## 1. 取代码

**方式 A（推荐，有远程仓库时）**

```bash
git clone <对方提供的仓库地址>
cd ai-video-pipeline
```

**方式 B（拿到的是 .bundle 单文件时）**

```bash
git clone ai-video-pipeline-YYYYMMDD.bundle ai-video-pipeline
cd ai-video-pipeline
git remote -v          # 此时没有 origin，需要时自己加：git remote add origin <地址>
```

> `.bundle` 包含**完整提交历史与所有分支**，等价于 clone 一个仓库。

---

## 2. 装依赖

```bash
# 推荐（lockfile 完整，可完全复现）
pnpm install --frozen-lockfile

# 退而求其次（仓库里的 package-lock.json 已过期，`npm ci` 会直接失败）
npm install
```

**为什么推荐 pnpm**（实测 2026-11-12）：

- `pnpm-lock.yaml` 完整覆盖 4 个直接依赖（express / ws / pg / @aws-sdk/client-s3）；
- `package-lock.json` **缺** `@aws-sdk/client-s3` 与 `pg`，`npm ci` 会报 `lock file's ... does not satisfy`；
- `npm install` 能装成功，但会重新解析版本，不是完全可复现。

> 若组织强制只用 npm：请先在有 npm 的机器上跑一次 `npm install`，把新生成的 `package-lock.json` 提交上来，之后 `npm ci` 才可用。

## 3. 配 `.env`

```bash
cp .env.example .env
```

**最小可跑（不配任何 Key 也能启动，生成走 Mock 模式）**：

```ini
PORT=3001
AUTH_ENABLED=true
AUTH_USER=admin
AUTH_PASSWORD=            # 留空 → 首次启动随机生成并打印在终端（只打印一次，记下来）
DATABASE_TYPE=json        # 没有数据库就用这个；用了 Postgres 改成 postgres 并填 DATABASE_URL
```

**要真实生成时再补**（按你用哪家填）：

```ini
# 通义万相 / DashScope
DASHSCOPE_API_KEY=
DASHSCOPE_MODEL_ID=wan3.0-video

# 或 OpenAI 兼容中转（WhaleTV / new-api）
OPENAI_VIDEO_API_KEY=
OPENAI_VIDEO_BASE_URL=
OPENAI_VIDEO_MODEL_ID=wan3.0-video

# 多模态质检（NSFW / 内容匹配）；不配 → 质检项判"未执行"= 不通过（这是刻意设计，见 README/红线）
OPENAI_MULTIMODAL_MODEL=
MULTIMODAL_API_KEY=
MULTIMODAL_BASE_URL=
```

> ⚠️ **不要**把 `.env` 提交进 git（已在 `.gitignore`）。交接时给对方的是 `.env.example`，Key 由对方自己申请。

## 4. 准备 ffmpeg

三种方式，代码按下面顺序自动解析（`config.js` 的 `resolveBundled()`）：

1. `.env` 的 `FFMPEG_PATH` / `FFPROBE_PATH`（显式优先）
2. 项目内 `tools/ffmpeg/bin/`
3. 系统 `PATH`

**方式 1：系统安装（Linux/容器最简单）**

```bash
# Debian/Ubuntu
apt-get update && apt-get install -y ffmpeg
# 然后 .env 里把 FFMPEG_PATH / FFPROBE_PATH 留空，让它走 PATH
```

**方式 2：放项目内（Windows 推荐）**

把 `ffmpeg.exe` / `ffprobe.exe` 放到 `tools/ffmpeg/bin/`（约 640 MB，**不在仓库里**）。

**方式 3：显式指定**

```ini
FFMPEG_PATH=D:\tools\ffmpeg\bin\ffmpeg.exe
FFPROBE_PATH=D:\tools\ffmpeg\bin\ffprobe.exe
```

> ⚠️ **许可证**：项目内自带的是 gyan.dev **full build，GPL v3**。作为独立进程调用不传染你的代码，但**随产品分发该二进制**需附 GPL 许可与源码获取方式。Debian 的 `ffmpeg` 包同样是 GPL 系，请按组织合规要求处理。

## 5. 启动与首次登录

```bash
node server.js        # 或 npm start / pnpm start
```

启动成功的标志（终端）：

```
FFmpeg 可用: true
FFmpeg 路径: <...>
服务已启动: http://localhost:3001
```

首次启动会用 `.env` 的 `AUTH_USER` / `AUTH_PASSWORD` 建第一个账号；密码留空时**随机生成并只打印一次**：

```
[auth] 首次启动创建管理员账号: admin / 8f3Ka9...
```

浏览器打开 `http://localhost:3001` → 会 302 到 `/app` → 未登录跳登录页。登录后：

- 成员管理：`/members.html`
- 健康检查（无需登录）：`GET /healthz`

## 6. 自检（部署完成必须跑）

```bash
node scripts/doctor.js
```

期望结尾：`结果: 0 个必须修复 / N 个提醒`，且退出码 0。

它检查：Node 版本、4 个依赖、两个 lockfile 的覆盖度、`package.json` 里的脚本是否存在、ffmpeg/ffprobe 能否执行、`.env` 是否覆盖代码读取的键、运行时目录可写、端口占用、配乐素材、许可证文件、日志体积、磁盘剩余。

`--json` 可输出机器可读结果（接 CI 用）。

## 7. 验收清单（逐条打勾）

| # | 检查 | 期望 |
|---|---|---|
| 1 | `node scripts/doctor.js` | 0 个 ERROR，退出码 0 |
| 2 | `curl http://127.0.0.1:3001/healthz` | `{"ok":true}` |
| 3 | 未登录访问 `curl -i http://127.0.0.1:3001/output/<任一mp4>` | **401**（2026-11-12 起媒体目录跟随登录墙） |
| 4 | 登录后同一条 URL | 200，能播放 |
| 5 | 登录错误密码 5 次 | 第 6 次返回 429 锁定 |
| 6 | 新建一个任务（Mock 模式，不填 Key） | 能走完 8 步并产出 `output/task_*_final.mp4` |
| 7 | 该成片用 ffprobe 看 | 有视频流；配乐步骤执行过则应有音频流 |
| 8 | 重启服务后访问页面 | 需要重新登录（会话在内存，属预期） |

> 第 6 步**不花钱**（Mock 模式）；要验证真实生成需要在 `.env` 填 Key 并承担费用。

## 8. 部署形态：三条硬约束（不遵守会出怪问题）

1. **只能单实例部署**。会话表、任务状态、生成任务、WebSocket 进度都在**进程内存**里：
   - 多副本 / 负载均衡 → 登录随机失效、任务状态前后不一致、进度推送丢失；
   - 滚动更新 = 运行中的生成任务被打断（重启后会被标记 `failed`，可补跑）。
   - 需要高可用时，先改造成共享会话 + 任务队列，那是另一个工程。
2. **必须挂持久卷**。`output/`、`clips/`、`data/` 都在本地磁盘；容器临时盘一重启就没了。
3. **反代必须支持 WebSocket Upgrade**，并注意三件事：
   - `TRUST_PROXY=true`（否则限流把所有人当一个 IP，一次攻击锁死全站）；
   - HTTPS 时 `COOKIE_SECURE=true`（或让反代透传 `X-Forwarded-Proto: https`）；
   - 上传配乐是 base64 JSON，反代 `client_max_body_size` 至少要 **64MB**（否则 413）。

## 9. 常见错误对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `npm ci` 报 lock 不满足 | `package-lock.json` 过期 | 改用 `pnpm install --frozen-lockfile`，或先 `npm install` 重新生成 lock |
| 启动就崩：`Cannot find module 'express'` | 没装依赖 / `node_modules` 不完整 | 按 §2 装；或从交付包恢复 `node_modules` 备份 |
| 页面能开但所有视频 404/401 | 媒体目录现在要求登录；或 `output/` 是空目录（新部署没有成片） | 登录后再试；先跑一个 Mock 任务产生成片 |
| `FFmpeg 可用: false` | 路径没配 / 二进制缺失 | 按 §4 配；`node -e "console.log(require('./config').FFMPEG_PATH)"` 确认 |
| 登录一直失败且提示锁定 | 反代后所有请求 IP 都是 127.0.0.1 | 设 `TRUST_PROXY=true` 并重启 |
| 上传配乐返回 413 | 反代请求体上限太小 | 调到 ≥64MB |
| 生成任务卡住不动 | 服务被重启 / 单实例被起了两个 | 确认只有一个进程；重启后任务需补跑 |
| 界面是新的、接口是旧的 | 改了 `src/**` 但没重启 | 重启；`node scripts/check-server-version.js` 退出码应为 0 |
