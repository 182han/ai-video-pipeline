## 4. 行为口径（下一位必须知道）

1. **触发**：`task.runtimeConfig.imagePerClip === true`，且不是 `source=library/regenerate`。旧链路（纯文生视频）行为零变化。
2. **出图**：就绪度/余额不足 → 任务失败并写原因，**绝不降级文生视频**；每张成功后才 `budget.reserve`；失败不自动重试（重试=额外计费，只能用户点补跑）。
3. **审图暂停**：`paused` + `awaitingImageReview=true` + `currentStep='等待审图：已出 N 张（待审 X / 失败 Y）'`；等待上限 `IMAGE_REVIEW_MAX_WAIT_MS`（默认 24h）；超时 → `failed` + `failureCode='image_review_timeout'` + `recoverable=true`。
4. **继续 = 审图信号**：`POST /api/tasks/:id/unpause`（前端「继续生成」）或 `POST /api/tasks/:id/continue`（补跑）都会结算：pending→approved（如实记 `autoApproved`），rejected→对应片段 failed，写 `reviewedAt/settledBy`。
5. **缺图硬守卫**：`imagePerClip` 任务里，片段没有 approved 首帧图 → 该片段 failed（错误含「缺少首帧图，拒绝降级为文生视频」），不发视频请求、不计费。
6. **被打回的图不自动重出**：要重出只能用户显式动作（当前还没有「重出这张图」入口，临时办法是在图片库把图改回 approved 再补跑）。
7. **调色**：参数绝对值（-100..100），每次从原图重渲染；输出 `clips/<photoId>_adjust_v<N>.png` 只增不覆盖；reset 回原图并保留 versions；不计费、不改 `cost/source`。
