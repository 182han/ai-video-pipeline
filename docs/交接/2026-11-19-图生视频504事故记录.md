## 6. 补跑后新发现的两个缺陷（2026-11-19 深夜，已修）

### 6.1 成功片段的 `duration` 从未写库 → 终检「接缝/色彩」永远「未执行」

- 现象：`task_mwnosz8o_uyl4.json` 与 DB 里 3 个 success 片段的 `duration` 都是 0；
  `qualityChecker.checkSeam` 拿不到片段时长，只能返回「未执行」→ 终检必然 `passed:false`。
- 影响：所有真实（非 Mock）任务都会在接缝/色彩两项上**永远假红**；且「未执行」被当成失败，
  无法区分「片子接缝真的差」和「检测器没跑」。
- 根因：`pipeline._finishClipSuccess()` 只写 status/qcResult/error（未写 duration），
  片段质检里其实已有实测值 `qcResult.details.duration.duration`（10.03）。
- 修复：成功收口时写入实测 duration（无则用任务配置兜底），并 `error: null` 清掉上一次失败的 504 文案。
  文件：`src/pipeline.js`；验收：`scripts/verify-pipeline-fixes.js` 第 [5] 组（3 项）。
- **重要**：修复后用真实时长复测这条成片，接缝/色彩**实测就是不合格**（3 段是不同地貌）：
  缝#1 SSIM 0.957 / MAD 17.15×，缝#2 SSIM 0.885 / MAD 46.5×（阈值 8×）；
  色差 ΔE 48.1 / 49.72（阈值 40）。所以它原本的「红」在修好后依然红，但原因变成**真实测量**而不是「未执行」。
  这是产品阈值/多场景设计问题，需要用户决定，不得偷偷放宽阈值。
- 本地复测命令（免费）：`node scripts/verify-seam-qc.js` 或直接调 `qualityChecker.checkSeam(final, [10.031,10.031,10.031], {fadeDuration:0.4})`。

### 6.2 异步落库乱序 + 无连接重试 → 数据库停在 `mixing`，成片已出却像没完成

- 现象：内存/本地 JSON 是 `completed`，DB 里 `task_mwnosz8o_uyl4` 却是 `mixing`、`output_path` 为空、
  `final_qc` 为空；若此时重启，启动时的僵尸回收会把这条**已完成**任务标成 failed。
- 根因：
  1) `taskManager._saveTask()` 对同一任务发起多个 `storage.saveTask()` 且不排序；较早的快照
     （mixing）可能后落库，把最终状态（completed）覆盖回去；
  2) 写库失败只 `console.error`，没有重试；Supabase/Neon 会掐空闲连接
     （日志：`Connection terminated due to connection timeout`，23:49:43）。
- 修复：
  1) 按 taskId 串行化落库（`src/taskManager.js` 的 `saveChains`），并提供 `flushSaves()` 供清理/收尾等待；
  2) 连接级瞬时错误自动重试一次并重建连接池（`src/storage/index.js` + `src/storage/drivers/postgres.js` 的 `resetPool()`）；
  3) 已用真实 DB 修复 `task_mwnosz8o_uyl4`：status=completed、3 个片段 duration=10.031、error=null（未改 finalQC 结论）。
  4) **本地 JSON 同步修复**：本仓库启动时只从 `data/tasks/*.json` 载入内存（`_loadAllTasks`；`reloadFromStorage` 未被 server 调用），
     DB 只是镜像；因此 JSON 也写回 duration=10.031 / error=null（UTF-8 无 BOM），否则重启后 UI 仍带旧 504 文案。
- 验收：`scripts/verify-pipeline-fixes.js` 第 [6] 组（3 项，模拟「第一笔慢、第二笔快」断言不并发乱序）；
  `scripts/_test-cleanup.js` 增加 `flushSaves` 等待，避免「删完又被迟到写入写回」。

## 7. 永久验收要求（追加）

7. 片段 success 必须写实测 `duration`（来自片段质检）；终检「未执行」不得被当作片段时长可用。
