## 1. 迭代队列（按建议顺序）

### R1 · 预算「计费不确定」人工对账入口（P0，建议下一轮）

**为什么**：task-3 已让网络类失败不再自动退款（`billingUncertain`），但**只有模块 API**
（`budget.listUncertain/resolveUncertain`），没有 HTTP 路由和 UI；下一次网络失败会出现
「余额被预扣、用户无法自助对账」。

- **写作用域**：
  - 研发：`server.js`（精确增量，禁整文件覆盖）、`src/budget.js`（只读复用，必要的小增量）、
    `scripts/verify-i18n-backend.js` / 新 `scripts/verify-budget-resolve-http.js`（临时隔离实例）。
  - UI：`web/src/screens/settingsPage.js` 或预算卡组件、`web/src/i18n/messages/{settings,common}.js`、
    `scripts/verify-assistant-frontend.js`（扩展静态断言）。
  - 文档：`PROGRESS.md`、`docs/spec/i18n-spec.md`（如新增 key）。
- **验收标准**：
  1. `GET /api/budget` 的 `uncertainCount/uncertainUsd/uncertainEntries` 可见（已有，补 live 断言）；
  2. `POST /api/budget/uncertain/resolve` 必须 `approved:true`，未批 → 400 `PAYMENT_NOT_APPROVED`；
     省略 `actualUsd` = 按全额计费（退款 0），给数字 = 退差额；幂等（第二次返回 null/无变化）；
  3. 负数/超预扣/未知 taskId → 400/404；全程零真实计费；
  4. 前端「待对账」列表 + 内联确认（不 `window.confirm`）+ 三态结果 + 中英词条对等；
  5. 套件：新 HTTP 套件全绿 + `verify-budget-uncertain` 41/0 不回归 + `verify-i18n --strict` 12/0 +
     `verify-assistant-frontend` ≥101/0；浏览器人工点一遍（不点真实 repair）。
- **红线**：不能调用 `POST /api/budget/set`；不能改历史 `settled` 条目；审计不得含 Key。
