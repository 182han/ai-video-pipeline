## 2. 根因（按发现顺序）

### 2.1 服务端文档级 Permissions-Policy 禁掉了麦克风

`server.js` 2026-11-12 安全加固时加了：

```http
Permissions-Policy: geolocation=(), microphone=(), camera=()
```

文档级策略优先级高于站点权限，所以 Chrome 里 `http://localhost:3001` 即使设成「允许」，
`navigator.mediaDevices.getUserMedia` 仍会抛 `NotAllowedError: Permission denied`。

已改为（`server.js:101`）：

```http
Permissions-Policy: geolocation=(), microphone=(self), camera=()
```

只放行同源页面的麦克风，camera / geolocation 继续禁用。**这是后端改动，必须重启生效。**

### 2.2 Chrome 默认麦克风选成了 ToDesk 虚拟声卡

`chrome://settings/content/microphone` 实测：

- 改前：`麦克风 (ToDesk Virtual Audio)`
- 改后：`阵列麦克风 (AMD Audio Device)（系统默认设置）`

ToDesk 虚拟声卡没有用户人声，ASR 收到的是杂音/静音，因此提示「没听清：只识别到标点/杂音」。
这是**本机 Chrome 设置，不在仓库里**。

> 如果用户是通过 ToDesk 远程操作这台电脑：应把 Chrome 默认麦克风改回
> `麦克风 (ToDesk Virtual Audio)`，并在 ToDesk 里打开**远程麦克风转发**；否则本机阵列麦克风听不到远端。

### 2.3 旧前端的反馈是死胡同 + 静音会产出垃圾字符

- 旧 `VoiceButton` 只回一行「拿不到麦克风权限…请改用打字」，不区分：已阻止 / 无设备 / 被占用 /
  非安全来源 / 文档策略拦截。
- 按住说话时如果用户在 Chrome 授权弹窗期间松手，`getUserMedia` 仍会稍后 resolve；
  旧代码会在授权通过后**偷偷开始录音且没有 pointerup 可停**。现由 `pressedRef` 拦截：
  授权晚到 → 立即停掉所有 track，提示「麦克风已允许，请再按住麦克风说一次」。
- 静音/噪声时 SenseVoice 会返回 `"."` 或 `"그."`（实测 3 秒静音 WAV → `{"ok":true,"text":"그.","lang":"ko"}`），
  旧前端原样塞进输入框，用户只看到一个点。
