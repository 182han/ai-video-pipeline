## 3. V2 六项能力（设计文档 §2 V2；Q19/Q20/Q21/Q23 决策）

1. **只读 `/api/assistant/context`（A–E 全量，Q12=A+B+C+D+E）**
   - A 任务：`tasks.{total,active,recent,failedRecent}`（含进度、失败原因）；
   - B 预算：与 `GET /api/budget` **同源**（同一个 `budget.status()`）；
   - C 素材：图片库（与 `GET /api/photos` 同口径：文件缺失不计入）/成片库/片段库/场景卡/BGM；
   - D 设置：Key **只 `{label,present}`**、模型与图生视频能力表、默认值、播报开关、服务版本（pid/startedAt）；
   - E 最近错误：读本机日志尾部 → `redact` 脱敏后摘要；
   - `ui.page` 由 `?page=` 上报（前端未集成时为 null，不假装知道）；`ui.draft` = 会话最后一条计划。
2. **任务播报（Q23=B：全局关键节点 + 合并节流 + 设置可关）**
   - 扫描 `taskManager.getAllTasks()`（不只小智自己的任务）：`task_created / task_started / task_failed / task_completed`；
   - 去重：`taskId:节点` 只播一次（announced 映射，含 eventId；有界淘汰）；
   - 合并：同一窗口多节点合成 1 条 `【小智简报】`；两次推送至少间隔 `throttleSec`（默认 30s）；
   - 开关：`broadcastEnabled`（默认开）；关闭期间只登记不补播；ring ≤200 / buffer ≤50 / seen ≤2000；
   - 推送：`wsManager.broadcastAssistant`（服务端 5s 定时扫描；首拍只登记历史、不补播）。
3. **失败诊断 + 一键修复建议（Q20=B：你点才做，L3 仍确认）**
   - `diagnose(task)` 只读输出 `category/reasons/suggestions`（预算/Key/模型能力/限流/超时/质检/媒体/未归类 8 类）；
   - `repairTask({approved:true})` 才执行；未确认 → `PAYMENT_NOT_APPROVED`，不调 `continueTask`；
   - 可执行动作仅 `continue`（复用已成功片段）；其它（换模型/降分辨率/补 Key/审图/充值）只给指引；
   - 执行写审计（kind=repair）。
4. **主动建议（Q19=B）**：预算不足（补跑会被闸门拒）、模型不支持 i2v、Key 未配置、限流、审图暂停、连续失败；只提示风险 + 替代方案，**不自动执行**（硬约束=不自动花钱）。
5. **跨会话偏好（Q15=B，可清空）**：服务端用户级 `data/assistant/preferences.json`（`ASSISTANT_PREFS_FILE` 可覆盖），白名单 `model/resolution/clipDurationSec/bgmStyle`；**Key/token/secret/password 字段一律拒绝**；`GET/POST/clear` 三端点；L3 未确认不写。
6. **专业管家简报口吻（Q21=B）+ 审计记录**：
   - 简报统一 `【小智简报】` 前缀 + `·` 条目（任务/素材/失败诊断/设置确认）；
   - 审计 `data/assistant/audit.jsonl` append-only（at/actor/kind/action/target/before/after/note；经 `redact`），`GET /api/assistant/audit` 只读可查。

## 7. 偏离设计 / 自主决定（逐条）

1. **播报范围取 Q23=B「全局」**（不是「只当前会话/自己任务」的旧默认）：扫全部任务；用「只播关键节点 + 合并节流 + 可关」控制打扰（设计 Q23=B 原文）。
2. **播报开关做成全局设置**（`preferences.global`），不是每用户独立：当前产品是单用户/单实例，前端未接设置页；代价是多人部署时一人关=全关（交付未验证，标限制）。
3. **节流默认 30 秒**；测试用 `scan(nowMs)` 注入时钟做确定性验证。ring 200 / buffer 50 / seen 2000 为有界上限。
4. **首拍 primeExisting**：服务启动后第一次扫描只登记已有任务、不补播历史（避免重启刷屏；关闭期间的事件也不补播）。
5. **偏好「不自动套用到排版」**：本轮只做服务端存储 + 读取 + L3 确认契约；新计划仍用 `planCard` 默认（openai-video/720p），**不偷偷改用户默认通道**（B6 是 L3 契约；前端设置页读取待集成）。
6. **context 的当前页面由前端上报**（`?page=`），草稿=会话最后计划；前端未集成时为 null，不假装。
7. **修复执行只开放 `continue`**（补跑/复用已成功片段）；换模型/降分辨率/补 Key/审图/充值只给指引（避免聊天里改设置或静默换模型）。
8. **L3 错误码沿用既有语义**：设置/偏好未确认 → `SETTINGS_NOT_APPROVED`；修复未确认 → `PAYMENT_NOT_APPROVED`；未改 `/api/assistant/execute` 的任何语义。
9. **`pendingChange` 存进程内存 + 10 分钟 TTL**（不落盘、不跨重启）；确认时必须带同一 `changeId`（防张冠李戴）。
10. **审计 append-only、不提供删除接口**（只读 GET）；每行 JSONL，读/写都过 `redact`。
11. **memo：④ 的 `xiaozhiPlan.js` / `createSmart.js` 两处前端文案均被 i18n 窗口整文件迁移接管（21:46/21:52）**——我未提交任何 `web/**`；语义保留在 `web/src/i18n/messages/{xiaozhi,createSmart}.js`（i18n 提交时一并带上）。本提交的 ④ 只含 `planCard.js` 与 `supervisor.js` 文案 + 断言。
