## 5. 遗留（不阻塞 V2，但请 V2 窗口开窗后先处理 1/2/3）

1. **中｜门禁套件会写用户真实冷却状态**：`verify-whaletv-video.js:51/63/65/67` 调 `planCard.buildPlan('5 分钟')` →
   `allocate(30)` → V1 后每次 `recordCooling()` 写真实 `data/assistant/scene-card-cooling.json`（该套件未隔离）。
   实测（Lead 复跑）：18:18:46 写入 3 个计划×30 张。**已删除该残留，恢复干净初始态**。
   修法：给该套件加 `process.env.SCENE_CARDS_COOLING_FILE = path.join(TMP, 'scene-card-cooling.json')`（V1 已对另两个套件这么做）。
2. **中低｜`/api/scene-cards/preview` 现在会写真实冷却**：`server.js:2728` 的 `allocate(count)` 默认 `recordCooling:true`，
   与注释「只读、不持久化」不符；点一次「看场景卡」即消耗一次冷却窗口。修法：`allocate(count, { recordCooling:false })`。
3. **中｜Key 有/无口径误导**：`supervisor.js keyPresence()` 只读服务端 `process.env`；实测 `.env` 里各 Key 值均为空
   （名称在、值为空），用户真实 Key 在**设置页 localStorage**（`vs_config`）。重启后小智会答「WhaleTV 中转 无」（§3 M6 实证）。
   修法二选一：① 措辞改为「服务端环境变量里的 Key」并提示“设置页里的 Key 小智看不到”；
   ② 前端在 `/api/assistant/message` 里带 `hasKey` 布尔（不传值），后端合并进 context。
4. **低｜文案未同步随机抽卡**：`planCard.describe()`、`supervisor.js:262` 问候语、`web/xiaozhiPlan.js:54`、`web/createSmart.js:270`
   仍写「按章节顺序自动抽取」（现在选卡随机、展示仍按章节排序）。另：「去掉场景卡 / 场景卡不要了」会被 diff 正则误接成改提示词，
   建议把关开关护栏从 `((不用|不要|关闭|别用|取消)\s*(场景卡|配乐|音乐|出图|图片))` 扩展到「去掉/不要了」语序。
5. **未验证**：浏览器视觉（卡片只在两时点出现/刷新后不弹卡）、30 分钟/180 段真实长片、冷却在真实多天使用下的观感。
