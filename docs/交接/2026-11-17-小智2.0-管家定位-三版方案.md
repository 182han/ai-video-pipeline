## 0. 定位：受控管家 agent（不是自主 agent）

**是**：有环境感知（L1 只读）、有工具权限（L2 改动 / L3 付费与破坏性）、会规划下一步、会主动提示风险、只服务本软件的内部 agent。
**不是**：有自己目标、会在无人发起时自己开任务/花钱的独立 agent。

四条不可破的共同契约（三版都一样）：

1. **卡片是确认凭证，不是聊天伴侣**：只在「开头计划成型」和「最终确认生成」两个时点出现；中间讨论不弹。
2. **L3 必确认**：发起生成/重跑/删除/改设置/重启，必须用户点确认；未确认 → `PAYMENT_NOT_APPROVED`。
3. **听不懂不猜**：不新建计划、不反问总时长；只给可选项；planId 不变。
4. **不静默**：失败/未执行/合法跳过分别呈现；`skipped ≠ passed`；Key 只回显"有/无"。

## 2. 三版方案（差异轴 = 自主度，按 Q22=A）

### V1 · 响应式工具管家（最小可控）

**一句话**：聊天里说人话就能改计划，卡片只在开头和最后确认出现；能查、能改，不能自作主张。

- **能力**
  - 意图兜底：「场景/场景卡 + 换/改/不满意」、「用这个：…」、「把第 N 段提示词给我看」、「把 X 改成 Y / 去掉 Z」；
  - 提示词工作流：展示某段提示词全文；按条应用修改；**一条消息多处修改按序全应用**；只回改动点（Q10=B）；
  - 用户自带文本：**原样替换**（Q9=A），不擅自润色；
  - 卡片两时点 + 「确认生成吗」→ 卡片 → 点确认才 execute；
  - L1 只读：当前计划、最近任务状态、预算余额、设置是否存在（Key 有/无）。
- **技术改动面**：`memory.js`（新入口词与优先级）、`supervisor.js`（scene/prompt 编辑 handler、context 组装）、`server.js`（只读 context 端点）、`assistant.js`（卡片可见性状态机 + 确认流程）、`verify-assistant.js`（断言）。
- **风险**：口语覆盖仍可能漏（需迭代词表）；不解决"全局环境感知"。
- **工作量**：中（约 2 个研发日/窗口）。
- **适合**：只想把"答非所问"根治、先稳住计划阶段。

### V2 · 半自主任务管家（推荐）

**一句话**：V1 全部 + 小智能看见整个软件、任务跑起来会主动播报和给修复建议，但**不主动开任务、不自动花钱**。

- **能力（在 V1 之上）**
  - `/api/assistant/context`（只读）：当前页面/草稿、任务列表与失败原因、预算、素材计数、设置存在性、服务版本、最近错误摘要；
  - 任务播报：进行中/失败时在聊天里发系统简报（只限你当前会话或你刚创建的任务，避免打扰）；
  - 失败诊断 + 一键修复：给"补跑/换模型/降分辨率"建议，**你点才执行**（Q20=B）；
  - 主动建议：预算不足、模型不支持图生视频、图片未审、连续失败（Q19=B）；
  - 跨会话偏好：记住默认通道/分辨率/BGM 风格/常用时长（Q15=B），设置页可清空；
  - 专业管家简报口吻（Q21=B）。
- **技术改动面**：V1 + context 端点 + `wsManager`/轮询接入前端 + 系统消息渲染 + 偏好存储 + 审计记录（谁在什么时候改了什么）。
- **风险**：主动播报打扰（用"只播报自己的任务 + 节流"控制）；WS 重连；偏好跨设备不一致（先存服务端用户级）。
- **工作量**：中-大（约 4–6 个研发日）。
- **适合**：你要的"管家感"——有数、会提醒、但分寸在你手里。**与你 Q17=B+监控建议、Q21=B、Q15=B 完全对齐。**

### V3 · 自主监控管家（最重，建议先不选）

**一句话**：V2 + 服务端后台巡检（任务/预算/失败/存储），主动建议队列，按授权自动处理。

- **能力（在 V2 之上）**
  - 后台定时巡检（事件总线 + 定时器），跨任务主动发现异常；
  - 建议队列（聊天里以"小智建议"卡片出现，可批量采纳）；
  - 按预设授权自动处理（如"失败自动补跑 ≤N 次"已有计划预授权，可扩展）；
  - 审计与周报（失败率/花费/时长统计）。
- **技术改动面**：V2 + 服务端调度与订阅 + 建议存储 + 设置开关（默认关）+ 审计报表。
- **风险**：打扰/资源占用/误判；默认必须关；本版不建议先做。
- **工作量**：大（1–2 周）。

## 3. 三版对比

| 维度 | V1 响应式工具管家 | V2 半自主任务管家（推荐） | V3 自主监控管家 |
|---|---|---|---|
| 卡片两时点 | ✅ | ✅ | ✅ |
| 意图兜底 / 提示词讨论 | ✅ | ✅ | ✅ |
| 环境感知（任务/素材/预算/诊断） | 部分（会话内） | ✅ 全只读 | ✅ 全只读 |
| 任务主动播报 / 失败修复建议 | ❌ | ✅（你点才做） | ✅ |
| 跨会话偏好 | ❌ | ✅ | ✅ |
| 后台主动巡检 / 自动处理 | ❌ | ❌ | ✅（默认关） |
| 改动面 | 小-中 | 中-大 | 大 |
| 工期（研发日） | ~2 | ~4–6 | ~10 |
| 体验 | 稳、够用 | **管家感** | 最强，但最容易打扰 |

**推荐路径**：先 V1（把截屏那类问题根治、可验收），紧接着 V2（补环境感知与播报）；V3 等 V2 跑一段时间再评估。

## 4. 验收脚本（按用户真实用词；V1 必过，V2 增量）

> 断言原则：**不新建计划（planId 不变）、不建任务、不反问总时长**；回复要点可核对。

| # | 用户说 | 小智应做 | 关键断言 |
|---|---|---|---|
| A1 | 换一个场景卡，我不太满意。 | 回「要换第几段？」（或按已有主语直接换） | `intent=plan_edit`；不含「排好了/做多长」；planId 不变；任务数不变 |
| A2 | 场景不太满意，场景卡就是提示词的内容。 | 同上；并区分「换卡 vs 改提示词」 | `intent=plan_edit`；planId 不变 |
| A3 | 第 2 张换一个。 | 只换第 2 张，回显「旧 → 新」 | 仅 index1 变；其余两段不变 |
| A4 | 把第 2 段的提示词给我看一下。 | 原样贴出第 2 段提示词（不弹新卡、不改任何东西） | 回复含该段全文；planId 不变 |
| A5 | 用这个：雪山日出，金光打在雪脊上，缓慢横移。 | 原样替换第 2 段，回「已按你的文本替换（17 字）」 | `promptOverrides['1']` 原文；planId 不变 |
| A6 | 把「缓慢横移」改成「缓慢推近」，去掉「金光」。 | 只应用这两处，回改动点 | `promptOverrides['1']` 同时含「推近」且不含「金光」；planId 不变 |
| A7 | 确认生成吗？ | 回确认语 + 给卡片 | 未点确认前**不建任务**；点后才有 task |
| A8 | 换一个场景，30 秒。 | 仍是新建计划（不能误伤） | `intent=create` |
| A9 | 10 分钟，场景从卡库选。 | 新建计划（无换卡动作） | `intent=create` |
| A10 | 配乐换一首。 | 配乐意图（不抢 plan_edit） | `intent=bgm` |
| V2-B1 | （任务跑到一半） | 主动简报「第 3/10 段生成中，约 X 分钟」 | 只在当前会话播报；节流 |
| V2-B2 | （任务失败） | 简报失败原因 + 一键修复建议 | 未点修复不执行 |
| V2-B3 | （余额不足） | 执行前提示「余额不足，建议…」 | 不建任务 |

## 5. 不做 / 边界

- 不主动开任务、不自动花钱、不在无人发起时执行 L3；
- 不操作软件外的东西（浏览器、系统、文件系统以外）；
- 不回显 Key；不读软件外隐私；
- 已付费生成不可"撤单"，只能中止/补跑；
- 不新增 npm 依赖（前端零构建约束不变）。
