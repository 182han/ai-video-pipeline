## 1. 事实修正（v1 的错误）

### 1.1 Key 不在 `.env`，在浏览器 `localStorage`

- 前端 `web/src/store.js:24` 读 `localStorage.vs_config`，字段 `llmKey / llmUrl / llmModel`；
- 每次请求随 body 发送（`assistant.js:474,760`、`taskDrawer.js:157`），**服务端从不持久化 Key**；
- 所以 v1 里"所有厂商 Key 都是空的"只对 `.env` 成立，**对对话链路是错的结论**；
- 已确认 DeepSeek 在用：`data/tasks/*.json` 里 `llmBaseUrl: https://api.deepseek.com/v1`、`llmModel: deepseek-chat`；
  另有两条任务用 `deepseek-v4-flash-0731`（走中转）。

**结论**：大脑**不缺 Key**；但需要前端在 `/api/assistant/message` 的 body 里带上 `llmApiKey/llmBaseUrl/llmModel`（今天只有 `/understand` 与建任务带）。

### 1.2 卡库英文化比 v1 判断的便宜一个量级

- 卡库是**数据文件**：`assets/scene-cards/v3.3-final.json`（200 张，327 KB）；
- 每卡 ~45 字段，其中**受控词表 ~10 个**（biome/landform/weather/season/light/shot/cameraAngle/lens/motion/palette），
  **自由中文 ~6 个**（feature/foreground/highlight_control/avoid/protagonist/end_lock）+ science.*；
- 关键：`src/i18n/templates/scene.js` **已经支持 `*_en` 字段**（注释原文："如果卡里提供 *_en 字段（未来英文卡库），优先使用"）；
- 所以英文卡库 = **纯数据任务**（加 `_en` 字段），代码侧几乎不用改；真正的成本是**审校**，不是翻译。

## 3. 方案 v2

### 3.1 架构（不变的部分）

```
用户话 → 路由层 ──命中白名单──→ 现有 regex 快路径（0ms，0 元）
              └─其余/歧义──→ 大脑 brain.js（LLM）
                              ↓ 输出 {say?, tool, args, clarify?, needConfirm?}
                          执行层 supervisor.*（幂等 + 审计 + 计费闸门）
                              ↓
                        say（接地校验后）+ key/params
```

四条护栏：**降级不倒退**、**钱不可由大脑直接花**（仍走 `execute(approved:true)`）、
**预算入账+日上限**（`llmPerCall` 口径）、**工具白名单**（未注册=拒绝）。

### 3.2 四个阶段 + 决策门

| 阶段 | 内容 | 依赖 | 用户能看到的 |
|---|---|---|---|
| **S0 止血** | unknown→澄清（不给菜单）；`提示词呢`/`场景卡看一下` 进词表（注释标"临时，待模型接管"）；"听懂→复述确认"；库四错；计划卡英文结构化 | 无 | 半天内：不再答非所问、库不出错、英文计划卡无中文 |
| **S1 影子** | `brain.js` 只读跑，**不改行为**；每次与 regex 结果比对，落 `data/assistant/brain-shadow-*.jsonl` | 需要 Key（浏览器随请求带） | 看不到变化，只看到日志 |
| **S2 切换** | 路由改为"白名单 + 模型"；fixture replay 测试；`say` 接地校验；预算入场 | S1 决策门通过 | 小智能听懂新说法、会反问、能聊 |
| **S3 英文补全** | 卡库 `*_en`（纯数据）+ live EN 扫描 + 费用/WS 结构化 | 可与 S1 并行 | 英文界面不再夹中文，卡预览有英文 |

**S1 的决策门（可测，不靠感觉）**：
- 指标：分歧条数 / 其中"模型更对"的比例 / 模型误报（把明确命令改错）比例；
- 通过条件：**误报 ≤ 2%** 且 **分歧中模型更对 ≥ 70%**，才允许 S2 切换；
- 不通过：保留 S0，不再往模型方向投。

### 3.3 「变聪明」的可测定义（这是验收，不是形容词）

1. **10 句真实原话 + 2 句从没出现过的新说法** → 每句必须"要么做对、要么问对"，不许第三种。
2. **3 个需要动脑的场景**：
   - 「这两段不连贯，能换成一个地方吗」→ 给出同场景替换方案
   - 「预算还剩多少，够做 2 分钟吗」→ 算给他，并在不够时给替代
   - 「上次那条为什么失败」→ 真实诊断 + 可执行修复项
3. 中英各跑一遍，英文侧输出不得含中文。
4. 延迟：快路径 ≤ 300ms；模型路径 ≤ 4s。
5. 费用：每轮 ≤ $0.001（`llmPerCall` 口径），日上限先设 $1。

| 支线 | 独占文件 | 只读 |

| A 换脑 | `src/assistant/brain.js`(新)、`src/assistant/memory.js`、`src/assistant/supervisor.js`、`src/services/llmService.js`、`server.js`(`/message`)、`web/src/components/assistant.js`、`scripts/verify-assistant-corpus.js`(新)、`scripts/verify-brain-shadow.js`(新) | `src/budget.js` |

| C 库 | `web/src/screens/inventory.js`、`web/src/i18n/messages/*` | `src/library.js` |

**冲突点**：`planCard.js` 只归 B；A 若需改动它，发消息给 B，不自己动。
**测试文件**：A 新增独立脚本；B 追加到 `verify-i18n-backend.js`；都**不重写** `verify-assistant.js`（只在 A0 加断言时增量 edit）。

## 10.2 好消息：回归金标准已经现成

`scripts/verify-assistant.js` 里已有 **87 条** `classify('原话').intent === 'xxx'` 断言（自 `:438` 起）。
这就是路由层天然的**金标准**：同一批话分别跑正则与模型，比较意图即可客观衡量"模型是否更强"，
**不需要新造语料，也不需要我自己当裁判**。

## 10.4 v3 修正（由上面推出来的，不是补丁）

## 10.5 复杂度账本（新增部件的成本与拆除方式）

**净判断**：新增约 900–1200 行与 2 份 prompt，换来"理解层"；
