# 界面主题分层规则

> 2026-10-27 定稿。此前每加一个页面都要争一次「要不要深色」，本文件给出唯一判据。
> 相关证据与实现见 `docs/spec/re-jianying/`（剪映 token）与 `docs/spec/changelog.md`。

## 唯一规则

> **深色 = 正在看画面的状态；浅色 = 操作状态。**

| 归类 | 判据 | 适用页面 |
|---|---|---|
| **深色** | 页面主体是**画面本身**（视频/时间线/预览），用户要判断色彩、亮度和构图 | 剪辑（`bgm-editor.html`）、影院/播放、全屏预览、登录页（全屏视频背景） |
| **浅色** | 页面主体是**表单、列表、配置、数据**，用户要读文字、填参数 | 工作台（`index.html`）、历史记录、片段库、配乐库存、成员管理、设置 |

## 为什么不是「整体统一深色」

1. **深色会压低文字可读性**：工作台大量表单与长文本，浅色底 + 深字更省力。
2. **浅色会干扰画面判断**：剪辑时周边白块会抬升感知亮度，导致调色/曝光判断偏移。
3. 剪映本身也是这么分的：编辑器深色，而其内置的管理类 Web 页面（素材发布、活动页）用浅色。

## 落地约定

- 新增页面时**先归类再选色**，不要按“好看”临时决定；归类写入该页的页面说明。
- 深色页统一使用剪映 `video-edit` token 集（`#141414 / #1c1c1c / #262626`、正文 `#e0e0e0`、强调 `#00cae0`、圆角 8）；
  浅色页沿用工作台现有 Notion 风变量（`--bg-primary / --text-primary / --accent`）。
- **同一页面内不混用**：深色页里的弹窗、菜单、输入框也必须深色（原生控件加 `color-scheme: dark`）。
- 例外只在整页替换时成立（例如登录页因为有全屏视频背景而保持深色）。
