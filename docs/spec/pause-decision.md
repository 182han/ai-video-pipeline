## 1. 身份与权限

**裁定：授予「研发 + 文档」两角色权限，不交叉。**

| 允许改 | 禁止改 |
|---|---|
| `app/src/**` | `app/web/**`（Lead 正在改） |
| `app/server.js` | `design/ui-ux/**`（Lead 的样板） |
| `app/scripts/**` | `app/output/**`（§4.7 红线） |
| `docs/spec/**` | `app/public/**`（已冻结，见 §2） |

**不需要 spawn 队友。** AGENTS §3 的本意是「别踩别人正在改的文件」，不是必须凑齐三个角色。
单 agent 场景下按**任务归属**分配，不按**角色名**分配。

## 2. 改哪套前端

**裁定：只改新版 `/app`（React + htm + vendor）。旧版 `app/public/index.html` 即日起冻结。**

- 旧版**不加功能、不改行为**；
- 旧版已有的暂停（`public/index.html` 按钮与逻辑）**保留不动**，作为回滚兜底；
- 所有新功能只进 `app/web/**`。

理由：旧版是迁移期出口，新版是目标态。两套同步改的维护成本已超过收益。

## 3. 文档与实现冲突：以实现为准

| 争议点 | 文档原写法 | 实现 | **裁定** |
|---|---|---|---|
| 未运行任务的状态码 | `409` | `400`（`server.js`） | **用 400**，改文档 |
| 恢复接口 | `POST /resume` | `POST /unpause` | **用 `/unpause`**（`/resume` 已被「用已成功片段继续」占用），改文档 |
| WebSocket 事件 | `task:paused` / `task:resumed` | 只有通用 `statusChange` | **暂不加专用事件**；前端读 `status==='paused'`。列入待办 |
| 返回体 | `doneClips` / `totalClips` / `atStep` | 只返回 `{success}` / `{paused,status}` | **不阻塞**，列为后续增强 |

改动范围：`docs/spec/pause-capability-spec.md` 由执行方按上表修正，并在 `docs/spec/changelog.md` 追加一条记录。

## 4. 缺陷修复范围

### 第一批（必须做，事故级）

1. **`paused` 重启后永久卡死**
   - 现象：`pipeline.js` 的 `IN_PROGRESS` 白名单不含 `paused`，且运行态是内存 Set；
     重启后点「继续」必然失败，用户无任何出口。
   - 要求：恢复路径必须可用，或明确降级为「可补跑」并给出提示。**不允许静默失败。**

2. **30 分钟静默丢弃**
   - 现象：超时后 `return false`，调用处只有一句 `return`，无日志、无状态变更，
     流水线继续跑并把 `paused` 覆盖成 `concatenating`。
   - 要求：必须有日志 + 明确状态变更。**不允许静默吞掉。**

### 第二批（延后，先文档化）

3. **暂停不覆盖拼接/转码**：唯一检查点在「取下一个片段之前」，
   拼接、转码期间按暂停只改状态字符串，给用户「已暂停」的假象。
   - **做法：写进已知限制，不实现。**

### 顺带修（允许）

4. `regenerating` / `processing` / `optimizing` 同样不在回收白名单——**属同类缺陷，允许一并修**，
   但提交信息里必须单独列出，不能混在「暂停」名下。

## 6. 验收口径

| 项 | 裁定 |
|---|---|
| 跑门禁 | **禁止在前台执行 `node scripts/verify-all.js`**（子进程 spawn EPERM）。改为**后台 job 逐个套件跑**，回收输出 |
| 验收脚本 | **必须新增 `verify-pause.js` 并注册进 `verify-all.js`**；不注册 = 假绿 = 违反 §4.8 |
| 动 `data/` | 允许，但**先备份**；被改动过的任务要在报告里列出 ID |
| 动 `app/output/` | **禁止**（§4.7） |
| 真实付费跑 | **暂不批准**。用可控慢速 stub 做验收脚手架（`scripts/` 属研发范围） |
| 结论 | 三态：通过 / 不通过 / 未验证；**未验证不得写成通过** |

## 7. 事实澄清（避免误判）

1. **「启动回收把 2 个 pending 标成 failed」不是 bug**，是 `reconcileInterruptedTasks()` 的既有设计行为。
   但它确实改动了运行时数据，**需在 changelog 记录被改的任务 ID**；若文件仍在，应告知可补跑恢复。
2. **`app/scripts/_audit2.mjs` 是 Lead 建的临时文件，已删除**，无需归因。
3. **`AGENTS.md` 过期由 Lead 负责更新**，执行方只需在报告里列出「文档与现状不符」的清单，不要自行改 AGENTS.md。
