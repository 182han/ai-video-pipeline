# 提示词助手悬浮球 · 需求

> 状态：已实施（2026-10-19）
> 归属：产品写需求 / UI 写前端 / 研发写接口
> 涉及路径：`app/public/index.html`、`app/server.js`、`app/src/services/llmService.js`

---

## 1. 痛点

当前流水线的提示词入口（`#promptInput`）**假设用户已经知道自己要写什么**：

- `/api/optimize-prompt` 在 `prompt` 为空时直接返回 400（`app/server.js`）
- `promptOptimizer.optimizeWithTemplate()` 是把用户已有的句子拼接模板词池
- LLM 分镜链 `llmService.storyboard()` 的输入是「主题/地区名」，仍需要用户先给出一个主题

因此存在两类用户卡死的情况：

1. **不知道写什么** —— 连主题都想不出来
2. **知道大概但写不好** —— 想拍「极光」，但不知道提示词该包含哪些要素

## 2. 目标

在网页内提供一个**随时可用的对话入口**，帮用户把模糊想法收敛成一条可用的视频生成提示词，并能一键填入现有的提示词框。

## 3. 交互形态

### 3.1 悬浮球

- 形态：**幽灵造型**（圆顶头 + 两侧圆钝角 + 3 道波浪尾），3D 质感
- 尺寸：96 × 96 px
- 位置：`position: fixed`，可拖动，位置记忆在 `localStorage.vs_assistant_pos`
- 可见范围：**所有页面**（不随侧边栏切页消失）
- 无底色，直接浮在页面背景上

### 3.2 四种状态与表情

| 状态 | 触发条件 | 表情 |
|---|---|---|
| `idle` 待机 | 面板关闭且鼠标未悬停 | 两只笑眼，右眼略大 |
| `hover` 悬停 | 鼠标移到球上 | 睁大双眼 + 双层高光，右眼更圆更大 |
| `think` 思考中 | 已发出请求、等待 LLM 返回 | 眼球上移露眼白，右眼略眯 |
| `talk` 说话 | 面板打开 | 张嘴，眼睛正常 |

视觉规格以 `design/ui-ux/assistant-ball-preview.html`（配色 1 · 冷白金）为准。

### 3.3 聊天面板

- 位置：根据球在屏幕的位置自动选择向左/右、向上/下展开，始终留在视口内
- 风格：微信式 —— 用户消息右对齐蓝底白字，助手消息左对齐灰底
- 关闭：面板「收起」按钮 或 `Esc`
- 球与面板**同时存在**（不同于微信那种球变关闭按钮）

## 4. 对话流程

```
点球 → 读 localStorage.vs_config.llmKey
  ├ 为空 → 显示「还没配置 LLM Key」卡片 + [去设置] 按钮 → openSettings()
  └ 有值 → 本地开场白（不消耗 token）
            → 用户输入 → POST /api/assistant/chat
            → 助手反问（每轮只问 1 个问题，可给 2–4 个选项）
            → 收齐「主体 + 时段/光线 + 运镜 + 情绪」后给出英文提示词
            → 渲染「使用这段提示词」按钮
            → 点击 → 填入 #promptInput → 派发 input 事件 → 切到创建页 → 关闭面板
```

## 5. 接口契约

### `POST /api/assistant/chat`

**请求**

```json
{
  "messages": [{"role": "user", "content": "我想拍个极光"}],
  "llmApiKey": "...",
  "llmBaseUrl": "...",
  "llmModel": "..."
}
```

**校验规则**

| 规则 | 行为 |
|---|---|
| `messages` 必须是非空数组 | 否则 `BAD_REQUEST` |
| `role` 只允许 `user` / `assistant` | 其它角色静默丢弃 |
| 最多保留最近 20 条 | 超出从头截断 |
| 总字符上限 20000 | 超出整条丢弃，不切半条 |

**响应**（一律 HTTP 200，用 `ok` 区分）

| 场景 | 响应 |
|---|---|
| 成功 | `{"ok":true,"ready":bool,"message":"...","prompt":"..."\|null}` |
| 无 Key | `{"ok":false,"error":"NO_LLM_KEY"}` |
| LLM 失败 | `{"ok":false,"error":"LLM_FAILED","message":"..."}` |
| 参数错误 | `{"ok":false,"error":"BAD_REQUEST","message":"..."}` |

**`ready` 的真实条件**：模型声明 `ready:true` **且** 实际给出了非空 `prompt` 才算 `ready`，防止模型说「完成」却没给正文。

## 6. 异常处理

| 场景 | 用户可见表现 |
|---|---|
| 未配置 Key | 面板内引导卡片，**不发请求** |
| Key 失效 / 401 | `⚠ 助手没有响应，请检查网络或 API Key 后重试` |
| 超时（30s） | 同上 |
| 网络中断 | `⚠ 网络异常：<原因>` |
| 返回非 JSON | 按纯文本渲染，不判为失败 |
| 请求失败 | **该条用户消息从上下文移除**，避免污染后续对话 |

## 7. 安全

- API Key 只走请求体，**不写入任何日志**
- 服务端优先用请求体里的 `llmApiKey`，否则回退到 `config.OPENAI_API_KEY`
- 不引入任何新 npm 依赖（用 Node 内置 `fetch`）

## 8. 验收方法

```powershell
cd "C:\Users\14872\Desktop\测试\app"
node server.js       # 访问 http://localhost:3001
```

1. **可见性**：切换四个侧边栏页面，球都在
2. **拖动**：拖到左上角 → F5 → 仍在左上角；`localStorage.getItem('vs_assistant_pos')` 有值
3. **无 Key**：清空 `vs_config.llmKey` → 点球 → 出现引导卡片，控制台无报错
4. **有 Key**：填入有效 Key → 说「我想拍个极光」→ 助手反问 → 走完出现「使用这段提示词」
5. **填入**：点击后 `#promptInput` 有值；多行时「批量模式」提示条出现（证明 `input` 已派发）
6. **异常**：断网发送 → 显示失败提示，且该消息不计入上下文

**接口单测**

```powershell
Invoke-RestMethod -Uri http://localhost:3001/api/assistant/chat -Method Post `
  -ContentType 'application/json' `
  -Body '{"messages":[{"role":"user","content":"拍极光"}]}'
# 无 Key 时应返回 ok:false, error:NO_LLM_KEY
```

## 9. 非目标

- 不做 Windows 桌面悬浮窗（结论：只做网页内）
- 不引入 Electron / Tauri / 任何 npm 包
- 不做无 Key 时的脚本问答树兜底（已明确选择「直接提示配置 Key」）
- 不做对话持久化（刷新即清空）
- 不修改 `src/pipeline.js`、`src/qualityChecker.js`
